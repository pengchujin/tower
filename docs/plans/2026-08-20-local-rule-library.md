# 本地规则集与当前规则分离实施计划

**目标：** 将用户创建的规则集保存到独立的本地规则库；只有用户点击加号后，规则集才加入当前方案。

**数据设计：** 新增 `LocalRuleSet` 保存名称、规则内容与远程来源；`CustomRuleFlow` 继续承担某个方案中的启用、策略组和路由绑定，并通过 `localRuleSetID` 引用本地规则集。旧版手工规则在读取快照时迁移为本地规则集，同时保留原有已加入状态。

## 任务 1：定义行为测试

- 验证保存本地规则集不会创建当前方案绑定。
- 验证点击添加后生成绑定，但本地规则集仍保留。
- 验证从当前方案移除后，本地规则集仍保留。
- 验证旧手工规则快照迁移后同时存在于本地库和当前方案。
- 验证界面采用“规则定制 / 当前规则 / 我的规则集 / 新建规则集 / 在线规则库”的信息架构。

## 任务 2：实现持久化模型与迁移

- 在 `CustomRuleFlow.swift` 新增 `LocalRuleSet`，并给 `CustomRuleFlow` 增加可选引用。
- 在 `AppSnapshot` 增加可选 `localRuleSets` 字段，确保旧快照可解码。
- 在 `AppModel` 增加保存、更新、删除、加入和移除本地规则集的方法。
- 加载旧快照时迁移手工规则；编辑本地规则集时同步所有已加入方案的规则内容与名称。

## 任务 3：调整规则定制界面

- 将页面标题改为“规则定制”，上方列表改为“当前规则”。
- 将创建区改为“我的规则集”，展示本地规则并提供独立加号。
- 创建和编辑只写入本地规则库，不自动加入当前方案。
- 从“当前规则”删除本地规则时只移除方案绑定；从“我的规则集”删除时明确删除本地内容及其所有绑定。
- 将“在线规则搜索”改为“在线规则库”，保留在线条目的按需加入逻辑。

## 任务 4：验证

- 先运行新增定向测试，再运行规则相关和全量测试。
- 检查本地化键一致性。
- 成功构建后检查连接的实体 iPhone，并在签名允许时安装和启动。
