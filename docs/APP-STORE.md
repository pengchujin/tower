# App Store 上架文案

给 App Store Connect 用的成稿。**定位是「配置文件转换工具」，不是代理工具**——这不是话术，是塔台的实际功能：它不建立隧道、不接管流量、不提供任何节点。

写法上有三条硬规矩，改文案时不要破坏：

1. **不出现** VPN、代理服务、翻墙、科学上网、加速器 这类词。塔台不是这些东西，写了会被归到需要组织类开发者账号的品类里。
2. 提到其他 App 时，说的是「配置文件格式」，不是「代理软件」。
3. 第一句必须说清楚它是转换工具，审核员通常只看开头。

## 关键词（100 字符以内）

用户看不到这个字段，它只影响搜索。每个语言各填一份。

**简体中文**（50/100）：

```
格式转换,节点管理,规则,策略组,分组,离线,隐私,不上传,批量,扫码,导入,导出,YAML,INI
```

**英文**（89/100）：

```
converter,format,config file,nodes,rules,policy group,offline,privacy,local,yaml,ini,json
```

四条规矩：

1. **逗号后不要空格。** 空格照样占字符，纯浪费。
2. **不要重复 App 名称和副标题里已有的词。** 那两处本来就被索引，再写一遍等于白填一格。副标题是「订阅转配置，全程在本机完成」，所以关键词里刻意没有「订阅」「配置」「本机」。
3. **不要填「工具」这类分类词。** 分类本身已被索引。
4. **不要填其他客户端的名字。** 那是别人的商标，会被判蹭词，是明确的拒审理由。

还剩一半字符空间。想加就加同义或长尾词，别把已有的词换个说法再写一遍——App Store 会自动把不同关键词组合成搜索短语，重复只是浪费。

## 推广文本（170 字符以内）

这是**唯一一个改了不用重新送审**的字段，显示在 App 描述的最上方。所以它该放会变的东西——当前版本的重点、临时公告——而不是长期不变的定位，那些属于描述正文。

**1.0 首发用这条**（65 字）：

```
订阅内容不会离开这台 iPhone。解析、分组、生成配置全部在本机完成，不经过任何在线转换服务。全部源码公开，每一条都能自己核对。
```

想更短就用这条（38 字）：

```
你的订阅内容不会离开这台 iPhone。转换全程在本机完成，源码公开可核对。
```

**以后发更新时换成这类**（67 字），首发不要用——1.0 没有"新增"可言：

```
新增 TUIC 与 Hysteria 支持，配置文件转换现已覆盖十二种协议格式。全部转换在你的 iPhone 上完成，订阅内容不上传。
```

## App 描述

```
塔台是一个在你 iPhone 上运行的配置文件转换工具。

它解决的是一件很具体的事：你手上有一份订阅文本，而你使用的客户端需要另一种格式的配置文件。塔台把前者转换成后者。

转换全部在这台设备上完成。订阅地址、节点信息和生成的配置文件不会上传到任何服务器，也不经过任何第三方在线转换服务。

■ 它做什么

· 读取订阅文本，识别其中的节点条目
· 支持十二种协议格式的解析与输出
· 生成七种客户端各自的配置文件格式
· 按国家和地区自动分组，生成对应的策略组
· 内置规则集，也可以导入你自己的规则
· 生成好的文件可以分享、复制，或直接交给同一台设备上的目标 App

■ 为什么在本机做

同类工具通常把订阅内容发到远程服务器转换。订阅文本里有服务器地址和密码，一旦发出去，你就无法确认它被怎么处理了。

塔台不发。转换器、规则快照和用于识别国家地区的 IP 数据库都随 App 一起打包，需要用到时直接在设备上查。

■ 关于联网

塔台只在三种情况下联网，每一种都由你按下按钮触发：获取你自己填写的订阅地址、导入你主动提供的规则链接、以及解析节点域名。除此之外它不会在后台或启动时发起任何请求。

国家和地区的识别不联网：先看节点名字，看不出来才查随 App 打包的离线数据库。你的服务器地址不会被发送出去查询。

■ 关于数据

塔台没有账号、没有统计、没有崩溃上报、没有广告，也没有任何第三方 SDK。它不收集任何数据。

写到磁盘的文件——包括导出的配置和二维码图片——使用 iOS 的完整文件保护，设备锁定时无法读取。

■ 代码是公开的

上面每一条都可以自己去代码里核对，而不用相信这段文字：
https://github.com/pengchujin/tower

■ 请注意

塔台是一个文件格式转换工具。它本身不建立任何网络连接隧道，不接管系统流量，也不提供任何服务器或节点。你需要自备订阅内容，并使用其他 App 来使用生成的配置。
```

（约 780 字，限制 4000）

最后那段「请注意」不要删。它同时是给用户的说明和给审核员的定位声明。

## App 审核信息 › 备注

审核员看的就是这一段，直接粘贴：

```
关于本 App 的定位：

塔台是一个文件格式转换工具。用户提供一份文本形式的订阅内容，App 将其解析并转换为其他客户端 App 所使用的配置文件格式（YAML、INI、JSON 等），供用户导出、分享或保存。

本 App 不包含 VPN 或代理功能：不使用 NetworkExtension，不创建任何网络隧道，不接管或转发系统流量，也不提供任何服务器或节点。用户必须自行拥有订阅内容，并使用其他 App 来实际使用转换出的配置文件。

关于数据收集：本 App 不收集任何用户数据。没有账号系统、没有分析统计、没有崩溃上报、没有广告，不含任何第三方 SDK。订阅内容和生成的配置文件只在设备本机处理，不上传到任何服务器，也不经过任何第三方在线转换服务。全部源码公开：https://github.com/pengchujin/tower

关于 App Transport Security 例外：本 App 在 Info.plist 中声明了 NSAllowsArbitraryLoads，原因有两点。一、用户输入的订阅地址由用户自己提供，其中一部分只提供 HTTP，主机名无法预先枚举为 ATS 例外域名；添加界面已明确提示 HTTP 传输为明文。二、将转换结果交给同一台设备上的目标 App 时，配置通过仅绑定 127.0.0.1、45 秒后自动失效的本地 HTTP 服务传递，不经过任何网络。

演示账号：不需要，App 无登录功能。App 内所有功能在没有订阅内容时也可浏览，测试转换功能需要用户自备一份订阅文本。
```

### 技术支持 / 营销网址

**技术支持 URL 是必填的，营销 URL 不是。**

支持页写在 `docs/support.md`，不是直接指向 issues 列表——审核员点进来要能看懂这个 App 是干什么的、用户遇到问题怎么办。页面里有常见问题（协议被跳过、重复配置、地区识别、乱码）和提交入口。

**营销 URL 建议留空。** 它是给有独立产品官网的 App 用的。塔台没有官网，填个仓库地址等于把同一个链接填两遍，对用户没有帮助，也不会让审核加分。空着完全正常。

两个页面都要先启用 GitHub Pages 才有 URL：仓库 Settings → Pages → Source 选 `main` 分支 `/docs` 目录。**提交前务必自己打开确认能访问**——填一个打不开的支持 URL 会被直接退回。

没启用 Pages 之前，可以先用 GitHub 的渲染页顶上，Apple 也接受：

```
https://github.com/pengchujin/tower/blob/main/docs/support.md
https://github.com/pengchujin/tower/blob/main/docs/privacy.md
```

### 销售范围

**建议排除中国大陆。** 这类工具在该区域基本无法通过审核，且可能牵连开发者账号。其他区域正常上架。这是产品决定，不是技术限制。

### 截图

工程当前是 `TARGETED_DEVICE_FAMILY = "1,2"`，**支持 iPad，因此 iPad 截图是必填项**。如果不打算认真适配 iPad，改成 `"1"` 只发 iPhone 会省掉一整类截图和一类审核风险。
