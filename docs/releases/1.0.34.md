# 塔台 1.0.34（82）

- Snell + ShadowTLS 节点导出到 Surge 时仍缺 `shadow-tls-password` 的问题（TestFlight 反馈，81）：1.0.34 之前粘贴保存的本地节点，启动时按原始节点行补回 ShadowTLS；编辑节点（包括 SS + ShadowTLS）保存后不再丢掉 ShadowTLS；Clash 订阅里 Snell 的 `plugin: shadow-tls` 不再被忽略，其他插件跳过并计数。

# 塔台 1.0.34（81）

- 导入 Surge 订阅：Snell 节点行里的 `shadow-tls-password` / `shadow-tls-sni` / `shadow-tls-version` 不再被忽略。以前这类节点导出到 Surge 后丢了 ShadowTLS，连不上；现在原样写回 Surge / Surge Mac，其他客户端（含 Surfboard）表达不了，跳过并计数。
- 导出 REALITY 节点：导入 Clash 订阅时保留 `reality-opts` 里的 `support-x25519mlkem768`，手动添加 REALITY 节点时可打开「服务端支持 X25519MLKEM768」，只写入 Mihomo 系配置。新版 Xray 服务端报「REALITY authentication failed」时打开即可（#57）；默认关闭，旧服务端不受影响。
- 局域网共享给 Surfboard：不再直接沿用 Surge 配置，按 Surfboard 文档过滤掉它加载不了的节点（SSH、TrustTunnel、MASQUE、VMess / Trojan 的 HTTPUpgrade、ShadowTLS、Snell v6、缺 `dns-server` / `mtu` 或带 `reserved` 的 WireGuard），避免整份配置导入失败。
- 导出到 FlClash、Clash Party：两者已带上 mihomo 1.19.34，支持 Snell v6；带 HTTP / TLS 混淆或 PSK 长度不合规的 v6 节点跳过并计数。旧版客户端需升级。
- 内置 ACL4SSR 规则更新到上游 `a7bdd9c`。

支持 iOS 17 及以上；Mac 安装包为 Apple silicon / Intel 通用版本。
